```text
  ├─ 工程状态：精确物理时间/频率、撤销/重做、文件/通道隔离
  ├─ 文件访问：File API / File System Access（受权限与兼容性约束）
  ├─ 本地计算：Web Workers + WebAssembly（可复用无 Qt 的 C++ DSP）
  ├─ 绘制：WebGL2（基线），可选 WebGPU，兼容回退及绘制诊断
  └─ 算法适配接口：BrowserCompute | LocalComputeService | FutureRemote
                                     │ 显式授权与版本化协议
                                     ▼
可选本地计算服务（独立进程、用户主动启动）
  ├─ native DSP / 大型数据分块处理与缓存
  ├─ FFSCN / SCN、TensorRT worker、模型管理和资源预检
  ├─ 任务队列、取消、进度、日志、结果/证据持久化
  └─ 严格本机监听、鉴权、路径权限及源文件访问安全
```

技术栈默认采用 **React + TypeScript + Vite**（模块边界清楚即可）、Zustand 或同级轻量状态管理、Vitest、Playwright；绘图采用自研可控制的 WebGL2 标量纹理+LUT，以及独立轴/游标/选择叠加层。WebGPU 只作为能力检测后的加速选项，不能成为首版唯一方案。较复杂的图谱不应仅依赖通用可视化库做全数据重绘。若团队有更优成熟方案，需提供兼容/性能/长期维护证据并经主 Bot 架构评审。

**核心原则：**

- 不把 Qt Widgets 或 QRhi 生硬编译到浏览器。优先复用、重构或重新编译**与 Qt 无关的领域和 DSP**；必要时将 QtCore/Windows 专属依赖抽离到适配层。每个复用模块都须有许可审查、编译可行性说明及数值对照测试。
- 用户仅需打开静态 Web 应用即可进行**普通本地 IQ 文件导入、基础时域/谱/时频可视化、手动标记和工程保存**；不能将全部核心功能依赖于一台始终在线的云服务器。
- 深度学习检测依赖 TensorRT/GPU 等浏览器不具备的原生能力时，使用**可选、明确标识的本地计算服务**；未运行服务、缺少模型或没有兼容设备时须可继续浏览器分析，不伪造检测结果，不强制上传文件。
- 后续可以支持远端部署，但必须在用户明确授权后传输数据，**默认离线本地优先**。若首版无法实现完全浏览器 DSP，应明确列为未满足项，而不是改成纯静态演示。
- 所有技术路径、依赖版本、文件格式、模型路径以真实审计结果决定。禁止虚构部署、性能和精度保证。

## 3. 必须维持的功能与交互契约

按**最新远端**建立 `SOURCE_TO_WEB_PARITY_MATRIX.md`，逐项标注当前能力、组件实现、迁移方式、证据、限制和负责人。最少包括：

### 3.1 工程/加载/持久化

- 新建/打开工程、工程树多文件、宽带到窄带通道切换、保存/重开与独立视图状态。
- RAW 数据支持实/复类型、int8/uint8/int16/int32/float32/float64、端序、IQ/QI/平面布局、多通道、头尾字节；SigMF、受支持 IQ WAV、源元数据及采样率/中心频率/有效带宽。
- 大文件使用范围读取、分块处理、取消、4 MiB 级分块或测量优化值；不能把整文件读入 JS ArrayBuffer 后才开始渲染。当前可用样本前缀与未读尾部必须区分。
- 兼容**原生工程 v6** 的字段/语义、标记与通道来源、创建快照和旧版本 v1–v5 迁移；浏览器不具备原始绝对路径权限时提供文件重新绑定、身份核验与明确提示。不能默默篡改 source path、转换数据或覆盖原文件。
- uint64 样本索引、半开区间和源坐标必须严格保持。JS 侧 `BigInt` 或十进制字符串承载精确索引；JSON 以已定义的十进制字符串协议编码，严禁通过普通 `Number` 无损序列化超过 `2^53` 的样本号。
- 保存建议使用显式下载或用户授权的 File System Access；使用 IndexedDB/OPFS 保存缓存、会话和可恢复草稿时说明权限、容量与迁移策略。工程/附属数据打包导出、原子性或等效安全保存与旧版备份语义需清楚规定。

### 3.2 真实图谱及可交互显示

- 宽带默认“时频研判”工作区：独立全局时间导航条、可切波形/PSD 的辅助图区、大时频图，并支持时频/瀑布物理轴转换。
- 缩放/拖拽/轴滚轮、时间频率范围、游标、驻留帧、ROI、矩形标记拖拽/顶点或边界调整、选择/取消选择、定位与历史动作。
- 瀑布：X=频率、Y=时间向下；时频：X=时间、Y=频率。交互以当前 X/Y 所代表的真实物理轴为准。
- PSD 的 Periodogram/Bartlett/Welch/DPSS/Burg 及平均/最大/最小等**源实现已支持项**按迁移矩阵明确划分真实实现和未实现；PSD/STFT 分开管理参数、缓存及统计时段。
- 符合源契约的物理频段点数 N、频率分辨率 `Δf=B/N`、可见频段内分析、足量观测/补零说明、线性功率聚合、dBFS/Hz 单位和可见范围，频带缩放不得伪称凭补零提高分辨率。
- 热图采用标量强度纹理和独立 LUT，色阶/参考电平改变不触发 FFT；交互预览与静止细化分离。图谱像素抽取不能污染实际检测数据、频率或标记坐标。
- 高 DPI、窗口变化和主/辅助/全局导航联动，避免鼠标手势与标记拖动冲突。主界面优先针对桌面浏览器（例如 1920×1080、2560×1440 的逻辑显示视口）验证，再扩展其它宽度，不照抄 Qt 设备特定的 DISPLAY 编号或屏幕固定条件。

### 3.3 标记、窄带与检测

- 三来源统一：原始样本标签、人工标记、算法结果，保留来源原文、修订、质量、证据和可追溯性；多段属于一个对象，选中、批量操作、软删除、撤销/重做和来源快照关系遵循原契约。
- 窄带基于 `LocatedSegment` 或 `UserRange` 创建通道，严格区分真实定位段与人工选取段；真实 CPU DDC/FIR/有理重采样须有数值一致性验证、有效前缀范围校验，不得从不可用尾部读数。
- FFSCN、SCN 独立 worker；只有确实连接并执行到后端才显示为“真实检测”。模型参数、FFT/hop/T/滑动、谱型、ROI/可见/全文件范围、任务快照、实际观测支持、短数据、取消前缀、失败/零结果区分、证据与工程重开对齐源实现。
- 源分支当前主 FFSCN/SCN 的 `down_nums=11`、模型频率网格至少 2048 且为 2 的幂、动态 FFSCN 档位及 SCN 当前部署引擎为模型包/适配规则；**不得擅自把特定 TensorRT engine 的 profile 认定为算法数学约束**。这些边界若源 HEAD 后续改变，依实际最新实现修订。
- 窄带星座/眼图/识别/解调在没有真实信号处理或模型能力之前必须醒目标记为“演示 / 未启用真实推理”，不制造假的精度或检测结论。

### 3.4 最新 UI 交互（不可回退）

- 单行图谱控制条：导航职责独立；波形/PSD 快捷项；主图模式/STFT N/色表/电平/显示/设置/ROI/标记等低频项溢出。
- 设置采用稳定、可自动收起的临时层：同入口切换，打开其它层、外部点击、Esc、页面失焦/跨上下文时遵守源草稿规则；内部下拉不能被误关。右侧四页常驻栏允许用户手动收起，不与临时层混淆。
- 显示/检测/标记/通道四页上下文导航；检测首屏聚焦模型/谱/范围/阈值/定位/预检/运行，专业与诊断折叠；运行按钮不随滚动丢失。
- 参数合法值只按 Enter、Tab/Shift+Tab 或应用内明确焦点切换提交；输入途中或窗口失焦不偷偷应用；非法草稿保留可恢复，Esc 可取消；数值控件和下拉滚轮不修改值，图谱滚轮及侧栏滚动仍生效。
- 检测入口显式、ROI 半开样本范围精确、历史派生复制冻结配置不自动运行；来源/详情查看不覆盖同文件草稿；任务取消始终绑定明确 `runId`，运行中修改展示不会改变已冻结的检测任务。

## 4. 多 Bot 协作组织与硬性责任

主 Bot 首先创建实际可工作的子 Bot；若可用 Bot 数有限，可以合并岗位，但**不能取消独立审查和测试**。建议角色：

| Bot | 主要职责 | 交付物 |
|---|---|---|
| **主 Bot / CAO** | 基线决策、总架构、跨模块接口、同步远端、集成、风险、发布签收 | 总计划、契约、集成记录、最终验收 |
| **Bot-A 源码与对等审计** | 最新 SHA、源码/测试/文档核验，真实/演示/依赖边界，差异追踪 | 审计、能力矩阵、`UPSTREAM_SYNC_LOG.md` |
| **Bot-B Web UI/UX** | 工程壳、宽窄带工作区、菜单/交互/临时设置层/状态 | 可操作的前端模块、Playwright 测试 |
| **Bot-C 绘图与性能** | WebGL2/WebGPU 可选、图谱、瓦片/抽取、物理轴、DPI、诊断 | 图谱引擎、交互/性能回归 |
| **Bot-D DSP 与文件** | RAW/SigMF/WAV、WASM/Workers、PSD/STFT、DDC/重采样、v6 格式 | 真实计算链、数据 golden 测试 |
| **Bot-E 检测与本地服务** | FFSCN/SCN 模型 worker、原生复用、协议、安全、任务取消 | 独立可选服务、真实推理冒烟测试 |
| **Bot-F 工程/标记/状态** | v6 导入导出、来源修订、通道快照、撤销/重做、精度 | 工程互操作和状态回归 |
| **Bot-G QA / DevOps / 安全** | CI、E2E、迁移矩阵验证、许可证、凭证、安装部署 | 全量验收报告、发布清单、CI 工作流 |

**并行规则：**

1. 主 Bot 先制定模块边界、状态 schema、API 契约、共享类型、目录归属、验收用例和 integration branch 策略，再授权各 Bot 写码；同一共享核心文件只允许一名明确 owner 持续维护。
2. 为每个 Bot 建独立任务包：背景、上游 SHA、负责文件/目录、输入接口、输出接口、禁止事项、测试命令、退出条件、交付提交/PR、阻断及回报格式。
3. 子 Bot 只在自己的分支/工作区提交，经过单元测试和主 Bot 的双向代码审查，再合并入新仓库的集成分支。禁止直接覆盖他人未提交工作，禁止未经审查强推 `main`。
4. Bot-A/QA 应与实现者独立，不能用“实现者说已通过”代替证据。出现接口变更必须广播所有受影响 Bot，更新契约后再集成。
5. 主 Bot 不能仅调度后就退出：负责把并行成果合并成**可整体运行的产品**，逐阶段运行集成回归、修复冲突，并确保最终 GitHub 仓库而非多个散落子项目交付。

## 7. 源分支变更对齐：必须循环执行，直至最终交付

这是用户新增的**强制约束**，由主 Bot 负责，Bot-A 专职巡检。

### 7.1 检查时机

- 启动 P0 时；
- **每个阶段开始前和结束后**；
- 每次跨 Bot 集成、重大数据/接口契约变更前；
- 每次准备发布 PR/合并主分支或推送正式交付前；
- 长任务期间，若 Bot 运行环境支持定时执行，建议每 **2 小时**巡检一次；否则在每次重新获得执行机会时先检查；
- 最终 push 完成后**再次**读取源 HEAD，验证交付状态是否仍对齐，记录观测时刻与 SHA。

只读参考命令示意（命令在新工程/隔离工作区执行）：

```powershell
# 必须在独立新工程或独立的临时目录执行，绝不在源本地目录写入
$remoteSource = 'https://github.com/yulongpo/signal_studio.git'
$sourceBranch = 'refs/heads/rebuild/a143-native'
git ls-remote $remoteSource $sourceBranch
```

### 7.2 新提交出现时的动作

1. 保留前一次已审计 SHA，获取当前最新 SHA。比对 `old_sha..new_sha` 的提交和文件差异；必要时在独立参考 clone 下载更新内容。
2. 将变化分类：`UI/UX`、`domain/contracts`、`DSP/data`、`detection/backend`、`persistence`、`docs/tests`、`dependencies/security`。
3. 逐项评估 Web 迁移影响，更新 `SOURCE_TO_WEB_PARITY_MATRIX.md`、接口版本、测试及 milestone；新能力对当前 Web 产品适用则实际实现，同步校验，而非只记录一句“已对齐”。
4. 通知受影响 Bot，安排增量任务/独立提交/代码复审，冲突通过主 Bot 评审后处理。不得无条件自动 cherry-pick Qt UI 或整体合并源分支历史；更不能反向写入源仓库。
5. 在 `docs/migration/UPSTREAM_SYNC_LOG.md` 中记录：时间、旧/新 SHA、涉及 commit、差异分类、Web 影响、实施提交、测试结果、未同步原因和关闭状态。
6. 对源分支新增的文档性或与 Web 无关的设备/Qt 环境改动，允许结论为 `N/A`，但必须具体说明；真正影响业务契约、功能或交互的变动不准漏迁移。

### 7.3 对齐和结束条件

- 验收不以“最新 HEAD 等于最初 SHA”为前提；以**最终 GitHub 远端新读到的源 SHA**为准。
- 未处理的适用差异为 0，或清楚标记具有客观阻断和已获用户允许的降级；绝不可将未实现差异标为已对齐。
- `docs/migration/UPSTREAM_BASELINE.json` 至少记录 `repo`、`branch`、`source_head`、`checked_at`、`web_commit`、`parity_status`、`open_deltas`、`source_diff_range`。
- 若源 HEAD 在最后一次测试之后移动，先做最终差异审计并完成必要回归，再发布；如果推送期间继续移动，在发布后再检查并产生下一批真实增量任务，不得伪称永久同步。
- 完成初版后，若 Grok Bot 平台支持持久任务，建立定时对齐任务；否则在**新仓库**加入只读 GitHub Actions 远端变更探测工作流，维护最后对齐 SHA，产生可执行的 issue/报告或 PR 检查清单；**不能把“发现新提交”冒充“自动完成代码迁移”**。若有可持续运行的 Bot 平台工作流，则继续完成修复、回归和 PR。任何监测产物、Issue、PR 只创建在新仓库。

## 8. 强制验收与质量门禁

### 8.1 源功能互操作

- 新版 Web 可从最小合法 IQ/SigMF 示例到“导入→波形/PSD/STFT→标记→窄带通道→DDC→保存→重开”形成实际完整链路。
- 原生 v6 工程在合理的浏览器文件重绑定后可读取/保存，来源、标记几何、多段、质量、通道关系与不可变快照行为正确；不应因重新保存而偷偷丢失未知字段，须记录 schema 扩展策略。
- 强制覆盖 uint64 大索引、半开端点、Hz 频率值、文件末尾/可用前缀、短记录/补零、无模型/无 GPU，以及切换文件/通道时丢弃迟到 worker 结果。
- DSP 用解析信号（双音、频偏、白噪声等）和源 C++/参考结果做误差有界的独立数值测试，报告指标与容差；“看起来相似”不合格。
- FFSCN/SCN 与源 worker 的冻结请求、输出物理坐标、任务取消以及身份/结果恢复，使用实际后端在可用硬件上验收；若模型资产缺失要记录路径、版本、hash、缺失原因和未跑项目，不能捏造通过。

### 8.2 Web 交互与安全

- 浏览器 Playwright 端到端交互：工具条、弹层、四页切换、ROI、拖动和顶点调整、任务运行/取消、跨文件草稿隔离、窗口缩放、撤销/重做、空状态与异常。
- 分别验证高 DPI、普通桌面窗口、WebGL2 路径和明确的 fallback；绘图后台任务不阻塞输入；性能数值须记录样本尺寸、浏览器/设备、帧预算、P50/P95 和失败情形，性能目标基于实际基线建立，不套用桌面原生报告当作 Web 测量。
- 本地计算服务默认只绑定 loopback (`127.0.0.1`/`::1`)，采用随机会话令牌或等效本机鉴权，严格校验 `Origin`、请求大小、文件访问授权和路径范围，阻止任意网页访问本地 IQ 文件或调用模型服务。远端服务器功能默认关闭。日志不得输出原始样本、访问凭证和用户隐私。
- 新代码无密钥/模型二进制/用户 IQ 数据泄漏；依赖许可和来源可追溯，CI 至少有 lint、typecheck、unit、build、e2e，native 服务能构建时追加其独立测试。

### 8.3 明确禁止的“假完成”

- 仅原型可点击但没有真实 IQ/DSP；
- 使用模拟 FFSCN/SCN 输出冒充真实推理；
- 只有 UI 截图或前端启动页、没有工程/标记/通道闭环；
- 删除或弱化失败断言、只跑一小部分测试就宣称全量通过；
- 声称浏览器执行 TensorRT，而实际只显示静态假结果；
- 用旧原生截图/CTest 数字当作新 Web 项目的验证；
- 只记下源分支新增提交，却不更新迁移代码及回归。
